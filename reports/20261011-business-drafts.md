# Actual-document local drafts for Shop forms

Donor customer, category, product, order and review forms stage changed business fields directly into local runtime Room Drafts at the final document path. Incomplete and invalid values remain local; no buffer type, content-localStorage store or recovery document is added. New-record Presentation State contains only an active final-path pointer. Product numeric inputs retain incomplete values such as `-` and `1.` as business-field draft values instead of erasing them.

The form observes the shared Room Draft. A serialized CAS loop reads current parts, preserves disjoint edits and first bases, and reapplies this tab's latest input after stale same-field overlap. Navigation/reopen and typing that races initial hydration preserve the local values. New-create pointers leave later edits to already saved records intact; a still-open create form can transition to field editing after another tab saves the record.

The installed React Admin mutation middleware is used at explicit submission. It flushes pending local writes and passes the exact current draft reference to the provider. The provider reads and validates the actual shared draft and its current Room relationships, not a stale full submitted form. Queueing consumes the exact revision without a blind replacement. Refusals, concurrent changes and provider-returned drafts are preserved. Existing direct/bulk writes keep their prior exact-base guards. Review accept/reject buttons submit through the form's Save boundary so locally typed comments accompany the explicit status decision.

The first product tab contains the lifecycle component, rather than introducing a fourth tab or mounting duplicate draft sessions. No route lazy import, navigation reload or added route read is introduced. Provider write-halt still permits local Save; real reach and security guards remain. No schema, Room data, binding, donor text or licence changes are included in this commit.

Tests cover invalid/local-only typing, reopened drafts, immediate unmount, shared-tab overlap/disjoint edits, first bases, exact-revision Save, races/refusals, saved creation lifecycle, local halt behavior and reach loss. The actual built bundle's opaque-origin DOM check covers dashboard, list navigation, Create Product's exact three tabs and actual business-field typing with direct network calls disabled. This is a local VM check, not hosted acceptance.

## Integrated image and draft verification

The composite also retains the donor image integration. A submitted new image reference is checked against the selected Room's locally declared attachment metadata; Save does not call a Provider Action or fetch bytes, even during provider write-halt. Only visible lazy image reads use the scoped byte/hash-verifying Action. The image selector retains a locally restored attachment reference as well as the opened record's reference. A failed typing-time local write blocks submitting an older draft revision and keeps the latest input in the open form.

Final composite local checks on 2026-10-11: typecheck, lint, 240 tests, eager build, static release audit, actual-bundle opaque-origin DOM startup/navigation/typing, audit positive/negative fixtures and license verification all passed. The release has 27 files totaling 3,011,797 bytes, one JavaScript asset, and no missing license files. The DOM harness supplies the standard structuredClone browser API absent from Happy DOM; denied storage/network conditions remain enforced. No live App publication, Room migration or hosted browser acceptance was performed by this integration worktree.
